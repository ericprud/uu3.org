fhir-slicer · FHIR profiles → ShEx over RDF collections

One systolic, one diastolic, anything else.

A FHIR profile slices a repeating element — “Observation.component must contain one systolic component and one diastolic component, others welcome.” In FHIR RDF that element is a first/rest collection, so the constraint becomes a walk down the list: a small state machine, one ShEx shape per state. Paste a StructureDefinition below, or load the blood-pressure example.

Examples

What the profile says

Each slice contributes a discriminator test and a cardinality; the slicing’s rules say whether non-matching members are allowed at all.

The list as a state machine

Each state remembers what the list still owes. Colored arrows consume a member matching that slice’s discriminator; the gray loop consumes a member matching none (allowed because the slicing is open). Green states may end in rdf:nil. Click a state to jump to its shape.

ShEx out

One shape per state; each fhir:rest points at the successor state’s shape. [rdf:nil] OR … marks the accepting states.

Reading the shapes

Each list shape answers one question: given what the list has produced so far, what may come next? Its alternatives (|) enumerate the permissible heads — one per slice that may still occur, plus, for open slicing, a catch-all whose fhir:first matches no discriminator and whose fhir:rest stays in the same state.

The <#LI_…> shapes test only the discriminator — that is what makes the NOT alternatives well-defined. A complete translation would conjoin the rest of each slice’s constraints onto the positive alternatives, e.g. fhir:first @<#LI_SystolicBP> AND @<#SystolicBP_content>, while the NOTs keep using the discriminator shape alone.

The same machinery reappears one level down: a patternCodeableConcept discriminator means “the fhir:coding list includes this Coding” — a one-slice slicing with min 1, max *. Its satisfied state is just “any well-formed list,” shared as <#AnyList>.

An instance the blood-pressure shapes accept (Turtle’s ( … ) is sugar for the rdf:first/rdf:rest chain the shapes actually walk):

<#obs> a fhir:Observation ;
  fhir:code [ fhir:coding ( [ fhir:system [ fhir:v "http://loinc.org"^^xsd:anyURI ] ;
                              fhir:code   [ fhir:v "85354-9" ] ] ) ] ;
  fhir:component (
    [ fhir:code  [ fhir:coding ( [ fhir:system [ fhir:v "http://loinc.org"^^xsd:anyURI ] ;
                                   fhir:code   [ fhir:v "8480-6" ] ] ) ] ;
      fhir:value [ a fhir:Quantity ; fhir:value [ fhir:v 107.0 ] ] ]      # systolic
    [ fhir:code  [ fhir:coding ( [ fhir:system [ fhir:v "http://loinc.org"^^xsd:anyURI ] ;
                                   fhir:code   [ fhir:v "8462-4" ] ] ) ] ;
      fhir:value [ a fhir:Quantity ; fhir:value [ fhir:v 60.0 ] ] ]       # diastolic
  ) .

Simplifications: only the first discriminator of a slicing is used; discriminators are assumed mutually exclusive (a head matching two slices would need product states); ordered is ignored and openAtEnd is treated as open; slice constraints beyond the discriminator are not emitted.
